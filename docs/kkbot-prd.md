# KKBot 产品需求

> 状态：持续演进
> 适用范围：KK9 Windows 客户端
> 跟踪方式：需求状态、阻塞关系和实施进度以 GitHub Issues 为准

本文只描述 KKBot 要解决的用户问题、产品行为和范围边界。架构、模块划分、第三方版本、数据库协议和实施步骤由当前总规格、有效 ADR 与对应 Issue 决定，不在本文件复制。

## 1. 产品目标

KKBot 为企业内部员工提供基于 KK9 一对一私聊的智能协作入口。在不修改 KK9 客户端源码的前提下，系统应可靠接收消息、调用企业知识与受控工具、协助生成人工可审计的回复，并把真实 KK 发送结果作为交付依据。

产品优先解决四类问题：

1. 员工在现有 KK 私聊中获得及时、连续的协助；
2. 企业知识回答可追溯到真实来源，不由模型编造内部规则；
3. 自动化动作受到权限、审批和人工接管约束；
4. 消息、交付和故障结果可审计，系统不因重试制造重复副作用。

## 2. 用户与场景

### Employee

通过 KK 私聊提出问题、查询组织信息、请求知识解释或发起受控业务动作的企业员工。

### Operator

使用同一 KK 账号处理人工会话的操作员。Operator 发言后，机器人必须停止争抢回复，并保留人工接管事实。

### Approver

对高风险动作作出批准或拒绝的授权人员。审批渠道、恢复语义和能力门槛以已生效决策为准。

## 3. 产品需求

### P1. 私聊消息接入

- 接收并规范化 KK9 一对一私聊消息。
- 同一原生消息不得因轮询、事件重放或重连被重复处理。
- 用户连续发送的短消息可在有限窗口内合并，避免机器人抢答半句话。
- 新消息、撤回或 Operator 接管能够停止仍在进行的自动回复。

### P2. 群聊边界

- 群聊消息可以作为原始事实被捕获和保存。
- 群聊不得触发自动回复、Agent、Memory、Tool、审批或主动发送。
- `@我`、`@全体`、引用、附件和当前账号发言都不能绕过该边界。

### P3. 回复与交付

- 支持向目标私聊发送文本、富文本、图片和文件。
- 只有 KK 返回的明确成功结果才表示消息已交付。
- 无法判断是否已经触发发送时，系统不得自动补发。
- 已发送、发送失败和结果不确定必须对运营人员可区分、可查询。
- 发送、撤回和人工处理结果必须保留必要审计信息。

### P4. 人工协作

- Operator 在客户端发言时，系统进入人工接管状态并阻止新的自动回复。
- 已经发生的消息、发送和外部工具副作用不得因接管或撤回被伪装成从未发生。
- 高风险工具只有在有效授权后才能执行；审批超时、重复决议和恢复不得重复执行原动作。

### P5. 组织信息

- 只读查询 KK9 中可见的员工、部门、岗位和汇报关系。
- 支持按稳定员工身份检索组织信息。
- 不通过机器人修改企业通讯录。

### P6. 企业知识

- 支持 Markdown、DOCX、文本 PDF，以及需要真实 OCR/Vision 的扫描文档和图片。
- 知识结果保留可返回原文件、页码或图像区域的来源定位。
- 企业制度、流程和规范问题必须先检索公共知识。
- 未找到可靠来源时明确说明不可回答，不能用模型常识补写企业事实。
- 删除、过期或未获授权的来源不得继续出现在新查询中。

### P7. 工具与外部能力

- 只读工具可以在权限和输入边界内直接执行。
- 写操作必须具备稳定业务身份和可审计结果，重复调用不能重复产生业务副作用。
- MCP 或其他外部工具不可用时，系统给出可诊断结果，不伪造成功。
- 工具结果必须经过与用户输入、模型输出一致的安全检查。

### P8. 运行与恢复

- 客户端断线、进程重启和依赖故障不得导致已知消息或交付被静默丢失。
- 结果不确定时优先保留事实并等待人工处理，不通过猜测恢复。
- 系统只有在必需依赖和观测能力可用后才开始处理新工作。
- 关闭时停止接收新工作，等待或中止在途任务，并释放已取得资源。

## 4. 产品非目标

- 不支持 Slack、飞书、企业微信等其他 IM 平台。
- 不建设群聊自动回复。
- 不建设多 Agent、微服务、消息队列或多主高可用架构。
- 不建设 Web 审批路径；人工授权通过约定的 KK 私聊完成。
- 不修改 KK9 客户端源码或绕过 KK 服务端权限与撤回限制。
- 不把模型生成成功、DOM 文本出现或本地内容哈希当作用户已收到消息的证明。

## 5. 产品验收结果

产品达到可交付状态时，至少能够证明：

1. 一对一私聊从入站、推理、知识或工具调用到单次 KK 发送完整贯通；
2. 群聊消息只保存原始事实，不进入自动处理链；
3. 断线、超时、撤回、人工接管和进程重启不会自动制造重复发送；
4. 企业知识回答包含真实来源，OCR 文档能回到原始位置；
5. 高风险动作未经有效批准不会执行，重复决议不会重复执行；
6. 真实 KK 冒烟、离线合同、故障注入和持久化恢复均留下可审计证据。

具体测试矩阵、实现状态和阶段退出条件不在本文件维护。
