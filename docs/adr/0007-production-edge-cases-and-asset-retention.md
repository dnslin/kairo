# ADR 0007: 生产级边界防护与组织架构汇报链路由规范

## Status

Partially Superseded

- §2 已由 [ADR 0010](./0010-single-composition-root-and-knowledge-lifecycle.md)、总规格 §4.18–§4.19 与 [#136](https://github.com/dnslin/kkbot/issues/136) 替代。
- §1 与 §4 保持 `Accepted`；§3 的 30 天物理淘汰规则继续有效，其引用保护、删除状态与崩溃恢复协议由总规格 §4.27 和 [#137](https://github.com/dnslin/kkbot/issues/137) 补全。

## Context

在 KKBot v2 迈向真实企业生产部署的过程中，需要明确组织架构汇报链的解析算法、多模态资产的存储生命周期、知识库更新时的向量一致性保障，并根据实测事实剔除不必要的过度设计。

## Decision

### 1. 三级确定性主管汇报链解析算法 (`LeaderHierarchyResolution`)

系统在需要审批拦截时，通过 `LeaderApprovalRouter` 按以下三级优先级确定性解析直属领导：

1. **第一级（个人直接主管）**：查询 `org_employees` 表，若该员工记录了 `leader_id`，直接命中其直属主管；
2. **第二级（部门层级汇报链追溯）**：若无个人直接主管，沿其主职部门树（`org_departments` 及其 `parent_id` 链条）向上递归检索，提取离申请人最近的一位部门负责人（`is_leader = 1`）；
3. **第三级（顶层高管兜底与防死锁）**：若申请人自身为最高级领导或向上汇报链为空，系统路由至配置的 `fallbackLeaderId`（如系统管理员/合规委员会）；若未配置则遵循 Fail-Closed 拒绝执行高危操作。

### 2. 知识库向量原子覆盖防脏读 (`AtomicVectorReplacement`)

> 本节以下原文仅保留历史决策背景，不再是当前 Knowledge 原子替换协议。

- 知识库文档更新时，系统以文档绝对/相对路径（`filePath`）为事务边界；
- 执行 **Delete-then-Insert** 原子替换，彻底物理删除旧切片向量后再写入新向量，杜绝新旧矛盾切片并存引发的事实幻觉。

### 3. 资产与交付物滚动淘汰策略 (`AssetRetentionPolicy`)

- 接收到的员工发票/截图（`data/media/`）与生成的交付物（`data/files/`）设置 **30 天** 物理文件滚动淘汰期；
- 数据库保留元数据记录，物理文件超期清理后访问返回“文件已过期”友好卡片，保障磁盘空间长期健康。

### 4. 剔除字数限制切分逻辑（遵循 YAGNI）

- 依据真机实测事实，KK9 客户端底层接口支持完整发送超长文本，**明确取消不必要的消息分段拆包逻辑**，保持单次原子完整回复。

## Consequences

- **Positive**:
  - 组织架构审批寻路逻辑严谨、透明且支持顶层高管兜底；
  - 知识库向量更新保证强一致性，无脏切片残留；
  - 磁盘空间自动自我维持，避免长期运行后物理暴满；
  - 避免过度设计，代码更加精简可靠。
- **Tradeoffs / Risks**:
  - 需要企业定期（如每日 03:00）同步最新的组织架构树以保证汇报链准确。
